# 12 — API Specification (REST + SSE)

> Related: [11 Data model](11-data-model-and-database.md) · [13 Dashboard](13-dashboard-ux-ui-spec.md) · [ADR-0009](adr/ADR-0009-backend-fastapi-pydantic-sqlalchemy.md) · [ADR-0011](adr/ADR-0011-server-sent-events-for-live-updates.md)

## 1. Conventions

| Topic | Rule |
|-------|------|
| Base URL | `{ROBOPROBE_API_BASE_URL}` (default `http://127.0.0.1:8000`), all routes under `/api/v1` |
| Versioning | URI major version (`/api/v1`). Additive changes (new fields/endpoints) are non-breaking; removals/renames require `/api/v2` and a 2-minor-release deprecation window with `Deprecation` + `Sunset` headers |
| Format | JSON (UTF-8), `snake_case` fields, RFC 3339 UTC timestamps, UUIDs as strings |
| Spec | OpenAPI 3.1 generated by FastAPI at `/api/v1/openapi.json`; committed snapshot `api/openapi.json` checked in CI (breaking-change diff with `oasdiff`) |
| Auth | V1: optional static bearer token (`ROBOPROBE_API_TOKEN`); if set, every request needs `Authorization: Bearer <token>` (SSE: `?token=` query param allowed because `EventSource` can't set headers) |
| Pagination | cursor-based: `?limit=50&cursor=<opaque>`; response `{items, next_cursor}`; max `limit` 500 |
| Filtering/sorting | explicit query params (`status`, `verdict`, `phase`, `sort=-finished_at`) |
| Idempotency | `POST` creating resources accepts `Idempotency-Key` header (stored 24 h) |
| Errors | RFC 9457 `application/problem+json` |
| Concurrency | mutable resources return `ETag`; `PATCH` requires `If-Match` (409/412 on conflict) |
| Rate limits | none (local tool) |

### 1.1 Error envelope

```json
{
  "type": "https://github.com/CodewithJha/RoboProbe/docs/errors#invalid-state-transition",
  "title": "Invalid state transition",
  "status": 409,
  "detail": "Campaign 0193… is COMPLETED; cannot pause.",
  "instance": "/api/v1/campaigns/0193…/pause",
  "code": "CAMPAIGN_INVALID_TRANSITION",
  "errors": []
}
```

Error codes (stable strings): `VALIDATION_ERROR` (422), `NOT_FOUND` (404), `CAMPAIGN_INVALID_TRANSITION` (409),
`SPACE_INVALID` (422), `BACKEND_UNSUPPORTED_PARAM` (422), `NO_WORKERS` (409, warning-level when starting), `PRECONDITION_FAILED` (412),
`UNAUTHORIZED` (401), `INTERNAL` (500, includes `trace_id`).

### 3.6 `SpaceValidationResult`

`POST /api/v1/spaces/validate` is a query: it returns HTTP 200 with `valid: false` rather than 422.

```json
{"valid": false, "errors": [{"pointer": "/parameters/2/high", "message": "high (0.5) must be greater than low (0.5)"}],
 "dimension": null, "enabled_params": []}
```

`POST /api/v1/spaces` returns 201 for a new `(id, version)` and 200 when the canonical content is
already stored; invalid content is 422 `SPACE_INVALID` with the same pointer list in `errors`.
The space registration and validation routes accept `application/yaml` or `application/json` and reject a body larger than
`api.max_upload_mb` with 413 before parsing.

### 3.7 SUT profile registration

`POST /api/v1/sut-profiles` accepts the complete profile document from
`schemas/sut_profile.schema.json` (including `schema_version: 1`) as YAML or JSON.
The same streaming `api.max_upload_mb` limit applies. The backend-specific config is validated
and defaults are filled before calculating `config_hash`, using the same loader as file-based
profiles. A new id returns 201, an identical repost returns 200, and an existing id with a
different hash returns 422 `VALIDATION_ERROR`; use a new id to compare changed configurations.
Space uploads resolve task paths relative to the configured API `space_root` and cannot escape it.

### 3.8 Campaign and manual-run creation

The CLI and API share `runner.CampaignFactory` validation: positive budget/repeats/batch,
configured caps, valid pins, backend support for unpinned parameters, strategy parameters and
resolved oracle thresholds. Registered space versions can be used without a matching file name;
shipped configs remain a convenience when no version is supplied. Config references cannot escape
`configs/scenario_spaces` or `configs/sut_profiles`.

Successful campaign creation returns `Location`. `Idempotency-Key` replays are persisted in
`idempotency_keys`; using a key for different content returns 422. `start: true` commits the
campaign before invoking its separate lifecycle transaction. Start responses warn with `NO_WORKERS`
when no fresh worker is available. Progress reports discovered modes, not the number of failures.
Manual requests apply campaign pins, normalize and hash values, derive repeat seeds from the
campaign seed, and respect `runner.max_manual_repeats` and `runner.manual_priority`.
Run filters are applied in SQL before keyset pagination; sort ties use run id, and null values
sort first in ascending order (last descending). Cursors must retain their original sort order.

### 3.9 Trace and artifact transport

`GET /api/v1/runs/{id}/trace?hz=10&columns=gt_x,gt_y,contact` returns
`{t, columns, hz, source_hz, truncated}`. `columns` is a comma-separated subset; time remains
in `t`. The target rate defaults to `api.trace_default_hz` and is capped at `api.trace_max_hz`.
Each time bucket retains its minimum clearance; endpoints and both sides of Boolean/status
transitions are retained as extra samples, so safety events can exceed the target rate.
`truncated` means samples were reduced or the requested rate was capped. Empty or single-sample
traces have no measurable `source_hz` (null). Invalid columns/rates return 422.

`Accept: application/vnd.apache.parquet` returns the original stored Parquet. Artifact downloads
resolve by id through the confined artifact-store path, stream as attachments, set a quoted
SHA-256 `ETag` and `X-Content-Type-Options: nosniff`, and sanitize filenames. Unsafe or missing
stored paths return 404 and emit `artifact.path_rejected` without revealing the path.

## 4. Server-Sent Events

`GET /api/v1/events?campaign_id=<id>` → `text/event-stream`; supports `Last-Event-ID` resume (event ids are `events.id`).
Heartbeat comment `: ping` every `api.sse.ping_interval_s` (15 s).

| Event `event:` | `data` payload |
|----------------|----------------|
| `campaign.updated` | `{campaign_id, status, counts, modes_found}` |
| `run.started` | `{run_id, campaign_id, ordinal, worker_id}` |
| `run.finished` | `{run_id, campaign_id, verdict, robustness, primary_failure, values}` |
| `mode.discovered` | `{campaign_id, mode_id, code, label, size}` |
| `analysis.finished` | `{campaign_id, analysis_id, kind}` |
| `worker.updated` | `{worker_id, status, last_heartbeat}` |
| `alert` | `{level, code, message, campaign_id?}` (e.g. `INFRA_UNHEALTHY`) |

## 5. Command semantics (campaign lifecycle)

| Command | Allowed from | Effect |
|---------|-------------|--------|
| `:start` | CREATED, PAUSED | → RUNNING; orchestrator picks it up |
| `:pause` | RUNNING | → PAUSED; no new runs enqueued; in-flight runs finish |
| `:resume` | PAUSED | → RUNNING |
| `:cancel` | CREATED, RUNNING, PAUSED | → CANCELLED; PENDING runs → CANCELLED; running episodes cancelled best-effort |

All return `202 Accepted` with the updated `Campaign` and are idempotent (repeating `:pause` on PAUSED returns 202, no-op).

## 6. Example session (curl)

```bash
API=http://127.0.0.1:8000/api/v1
curl -s -X POST $API/spaces -H 'Content-Type: application/yaml' --data-binary @configs/scenario_spaces/warehouse_v1.yaml
curl -s -X POST $API/campaigns -H 'Content-Type: application/json' -d @configs/campaigns/k2d_probe_200.json
curl -N "$API/events?campaign_id=<id>"
curl -s "$API/campaigns/<id>/modes" | jq '.items[] | {code,label,size}'
```

## 7. Non-functional

p95 ≤ 200 ms for list endpoints at 10 000 runs (keyset pagination + indexes in 11 §3); trace endpoint
downsamples server-side; responses gzip-compressed (`GZipMiddleware`, min 1 KB); CORS allow-list from
`ROBOPROBE_API_CORS_ORIGINS` (no wildcard).
